## 非重叠区间对的最低费用

`PricedInterval { int64_t begin, end, cost; }` 表示 `[begin,end)`。输入为只借用的 `span<const PricedInterval>`，各区间非空，费用非负，`total_duration` 在 `[1,INT64_MAX]`。端点支持完整 int64 范围，但单段长度须能放入 int64。相同区间或相同费用仍是不同的输入项。返回 `optional<DisjointIntervalPair>`，含精确总费用与原始输入编号，`first` 区间在 `second` 之前，任意一个最低费用方案均可；无解为 nullopt，空输入无解。

非法目标、空/反向区间、负费用抛 invalid_argument；长度超过 INT64_MAX 抛 overflow_error。最佳总费用超过 INT64_MAX 才抛 overflow_error：非最佳溢出候选被跳过，因此不会因无关昂贵方案拒绝可表示的最优解。分配异常正常传播。返回不依赖输入生命周期，函数不修改输入。

按 begin 扫描右区间，按 end 向状态中加入已结束的左区间。状态对每个**原始长度**只保留最低费用及编号。处理右区间时，所有且仅有满足 `left.end <= right.begin` 的区间已加入；长度为 `target-right_length` 的最小费用就是该右区间的最优左搭档。每对合法区间在其右区间处被考虑，从而得到全局最优。正长度保证不把当前区间或同起点的未来区间错误加入。

排序和压缩 O(n log(n+1))，扫描含二分查询 O(n log(u+1))，u 为不同长度数；整体 O(n log(n+1))，O(n+u) 额外存储、O(log n) 排序调用栈，输出 O(1)。64-bit 平台两份排序索引 16n 字节，长度键容量至多 16u 字节，最小费用及编号 16u 字节；压缩初始排序副本 8n 字节，缩容时有临时复制。上述为数组载荷，非测量的进程峰值。

这里无需线段树：状态只有单点取最小、单点查询，没有范围聚合。若长度上限较小且稠密，可用直接长度数组省去压缩二分，但需 O(最大长度) 空间；当前 API 面向稀疏大端点。区间合并和最少区间覆盖接口都不保留本题费用与恰好两项的约束，不能直接替代。

CF 的输入是闭区间整数天 `[l,r]`，适配器将其转成 `[l,r+1)`；只因官方 `r<=200000` 才安全执行 `r+1`。通用 API 没有偷偷把任意闭区间按此方式转换。

## 有限步差的最长子序列

`bounded_step_subsequence_length(span<const int64_t> values, int64_t max_difference)` 返回精确 size_t 长度，不返回实际子序列。值支持完整 int64 范围；差上限限 `[0,INT64_MAX]`，负上限抛 invalid_argument。空输入返回 0，重复值和上限 0 合法。输入只借用且不修改，不排序原序列。分配/容器尺寸限制另外适用。

在处理当前位置之前，线段树每个键存储先前已处理位置中以该值结束的最长长度。合法前驱值范围为 `[value-gap,value+gap]`；在完整 int64 边界处做饱和端点构造而不执行溢出运算，再用 lower_rank 找半开坐标范围。先查询、再写当前值，确保不在同一步重复使用当前元素。转移是 `1 + range_max`，同值状态保留最大值。归纳得到所有前缀的最佳长度。

压缩只保持序，不保持距离。`[0,100,101]` 在 gap=1 时答案 2；按相邻压缩排名认为三者都接近，会错误输出 3。SparseTable 虽可做静态 max，但当前 DP 每一步更新状态，不能直接替代 SegmentTree。

压缩 O(n log(n+1))，扫描 O(n log(u+1))，整体 O(n log(n+1))，O(n+u) 临时存储、O(log n) 排序调用栈。64-bit 平台树 16u 字节，压缩键容量最多 16u 字节；初始化零数组 8u 字节在扫描前释放，压缩排序副本 8n 字节及缩容临时副本另计。上限 gap=0 或覆盖全部输入值有更简单的特殊路径，但当前接口没有声称在所有工作负载下性能最优。

## 树上全部最远距离

`tree_eccentricities(n, span<const UnweightedCsrGraph::Edge> edges, source=0)` 的边按无向边每条只列一次。`1 <= n < UINT32_MAX`、source 合法、恰好 n-1 边，必须连通；它内部双向建 CSR。返回所有点到指定 source 的单位边距离、各点到最远点的单位边距离，以及一对直径端点和直径长度。单点树返回两个零数组及直径 0。没有权重参数，不能直接处理不等长边、一般图或森林。

非法点数/边数/不连通抛 invalid_argument，越界 source 或边端点抛 out_of_range。先检查边数，再用 CSR 的第一轮遍历检查连通性：n-1 条边且连通的无向多重图必然是一棵简单树，因此自环、重边和非树环结构都无法通过，不额外保留 DSU。输入只借用、返回数组独立拥有，分配限制另外适用。

从 source 的最远点 a 是某条直径端点，从 a 的最远点 b 得到直径；树中任意点 v 的离心率为 `max(dist(v,a),dist(v,b))`。其依据是树上唯一路径：把支路投影到 a-b 直径上，任何支路高度不能使其到任一端点距离超过直径长度，故其它点到 v 的距离不超过 v 到这两个端点中的较大值。三次 BFS 得到所需数组，不使用递归或优先队列。

建图、三次遍历、合并都是 O(n)，读完所有边以及产生 n 个结果本就需要 Ω(n)，仅在该单位树输入/输出模型下达到渐进时间最优。队列重复使用，O(n) 存储，O(1) 调用栈。64-bit 平台 CSR 逻辑载荷约 16n 字节，遍历时队列 4n、三个距离数组 12n；建图时双向弧列表和 CSR/游标同时活跃，逻辑载荷约 40n，比遍历阶段更大。返回两个数组 8n 字节，不把输出存储隐去；实际分配/进程峰值未测量。

CF1822F 将树售价写成 `k*eccentricity[v]`，移动根的最少费用为 `c*dist(source,v)`，逐点取最大差值。官方 n<=200000、k,c<=1e9，乘积小于 2e14，int64 足够；这些业务系数只在适配器中处理。它也可用于无向树网络的中心候选、最坏延迟分析，而非仅服务该题。

## 状态、能力与未覆盖范围

三项函数都在调用内新建局部状态，返回只包含值/拥有的数组。没有 persistent、snapshot、checkpoint、rollback、undo、redo、在线删点或动态更新接口。同一不变输入可并发调用，但调用者不得同时改动借用输入。算法均为精确整数，没有浮点容差限制。

候选还包括博客中的 Delivery Route（非负块内最短路 + 带符号的块间 DAG）及笔记 CF319C（动态直线最小值 DP）。它们尚未验证；前者可以探索每个块入口统一平移后虚源 Dijkstra，但需要证明跨块顺序、范围及重建成本。后者缺少当前库已实现的直线包络查询原语；普通 min 线段树存标量，不能自动回答变化 x 上的直线最小值。先记录范围与缺口，再决定是否扩展，不把未实现的组合列成可用资产。
