# 首批资产架构验证记录

日期：2026-10-13（Asia/Shanghai）。范围：5 个算法、1 个图表示、1 个组合配方及最小目录匹配工具。

## 结论

“直接 include 的实现 + 结构化契约 + 已验证配方 + 明确缺口”这条核心路径已通过首批试验。通用新组合搜索、准确资源预算和 ML/优化/几何的跨领域组合仍未实现，不能以这次结果宣称七项目标已全部达成。

## 验证事实

- GCC 15.2.0 / Windows x86-64 MinGW，CMake 4.1.0，C++20。
- Release 构建无本次启用的编译警告，CTest 三组通过：算法与配方、契约校验、目录匹配。
- 9 个公共头文件各自独立包含编译，随后进行多翻译单元链接。
- 两个独立消费工程分别使用 add_subdirectory 和安装后的 find_package，运行实际算法对照测试均通过。
- libstdc++ 调试迭代器/边界检查以及 -Wall -Wextra -Wpedantic -Werror 构建运行通过。
- 尝试 UBSan 链接时当前 MinGW 缺少 libubsan，故未完成 UBSan 检查；不得将调试检查视为 sanitizer 等价替代。
- 参考仓库保持干净，未修改参考文件。

## 七项目标的当前证据

1. 已能从结构化问题规格匹配首批单实现；不是自然语言算法发现器。
2. 已能匹配并调用已有配方，提供符号复杂度；尚不能搜索新配方或证明时间/峰值内存预算成立。
3. 已记录 API、前置条件、错误、数值、状态、所有权及历史能力；结合律等语义前提仍需调用者核实。
4. 已有替代、依赖、组合与表示关联，以及条件不匹配理由；尚无一般归约/信息损失推理。
5. 数值求和已展示精确算法与近似数值契约能共存；ML、优化、几何扩展仍待真实资产验证。
6. 代码、可运行示例与关键不变量说明共同维护；阅读友好性仍需真实使用反馈。
7. 在线删边被明确拒绝并保存到 gaps；没有静默换用离线算法或自动增加新算法。

## 试验带来的设计修正

- 紧凑 2n 线段树不能将物理根无条件解释为有序全区间结果，all_fold 保留 O(log n) 查询。
- 回滚深度只表示当前祖先历史，不是持久化版本 ID；能力目录须保留这一限制。
- 配方内的时间树负责分发边生存区间，语义不同于幺半群聚合，不强行复用普通线段树。
- Dijkstra 对超长候选途径和真正超出距离范围的可达点作不同处理，不混淆不可达与溢出。
- 内存载荷下界用于确定拒绝明显超预算，但不能证明可运行；目录候选保持 resource_status=unknown。
