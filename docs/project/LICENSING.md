# 开源许可与贡献政策

自2026-10-20起，AlgorithmAssets自有代码、工具、测试、契约和文档采用标准 [MIT许可证](../../LICENSE)。版权声明使用 `Copyright (c) 2026 RyanTsi and contributors`；贡献者保留各自贡献的版权，不将他们的代码登记成维护者独有。根目录英文LICENSE为许可正文，本文解释范围和工程做法，不给MIT添加额外限制。

## 为什么选择MIT

目标是让其他人容易接入、愿意贡献，也保留作者将代码用于商业或闭源项目的空间。MIT允许使用、修改、分发、再许可与销售，要求在副本或实质性部分中保留版权和许可声明，并包含无担保条款。它不要求回馈修改、不禁止商业竞争，也不要求使用者在产品界面展示项目名称。参见 [OSI的MIT正文](https://opensource.org/license/mit)。

维护者和外部使用者适用相同的MIT权限。MIT贡献可以用于独立的闭源产品，但收到贡献不等于取得贡献者的独占版权。不能通过后来修改仓库许可，让已经按MIT获得代码的用户自动失去该版本的授权。若未来需要MIT范围以外的权利，应与相应权利人另行协商；本轮没有版权转让或CLA。

## 授权范围

| 内容 | 适用规则 |
| --- | --- |
| 项目自有实现、示例、测试、工具、契约、文档和原创元数据 | MIT，除非文件已有单独适用声明 |
| `third_party/eigen3/` | 上游Eigen条款；主体MPL-2.0，逐文件与COPYING为准 |
| `provenance/`中外部原文、用户提供的原模板及外部资料 | 原有权利与许可；根目录MIT不自动重新授权这些材料 |
| 平台题面、截图、标识与其他外部验证材料 | 原权利人的条款，不因存入本仓库而转成MIT |
| 历史判题快照 | 项目自有部分适用MIT，第三方部分按原条款；文件与哈希不改写 |
| 工作区参考仓库与链接的外部仓库 | 独立许可边界；本项目不替其授权 |

更具体的分发说明见 [第三方声明](../../THIRD_PARTY_NOTICES.md) 与 [Eigen集成说明](../../third_party/README.md)。Eigen的MPL覆盖部分有自身声明与源码提供义务，不能只附MIT就视为履行全部条件；MPL并不要求把未含其代码的独立文件一并开源。参见 [Mozilla MPL FAQ](https://www.mozilla.org/en-US/MPL/2.0/FAQ/)。

源仓库在固定快照中没有发现LICENSE，是历史来源事实；本次仅为当前项目有权授权的内容选择MIT，不替来源中的其他权利人补授权。原始来源清单、模板、上游文件与历史验证哈希保留原样。

## 接收贡献

采用同入同出：新提交的自有贡献按MIT授权，已存在的第三方内容保留原条款。贡献者应有权提交内容，并在新提交中加入DCO 1.1 sign-off。DCO用于确认来源权利，不转移版权，也不能将不兼容或未知许可代码变成MIT。完整工作方式见 [贡献指南](../../CONTRIBUTING.md) 与 [DCO原文](https://developercertificate.org/)。

我们没有另设强制版权转让、独占授权或禁止商业使用的附加条件。第三方模块和特殊授权先明确范围再合并；仅有网址、算法名称或“网上找到的代码”不足以证明复制权。Git历史保留贡献归属，需要时在文件或来源记录中保留作者及原始声明。

## 分发与安装

源码仓库提供根目录LICENSE及第三方声明。CMake安装包会将这两份文件安装到配置的数据目录下的 `AlgorithmAssets/`，并继续分发Eigen头文件和对应 `licenses/eigen3/COPYING.*`。提取单个头文件或组合成单文件分发时，也需携带适用的版权与许可声明；“header-only”不免除这些要求。

本轮同步91项资产契约与独立正文中的许可状态、来源台账生成说明和安装规则，不改写算法实现及上游条款。许可说明不是对来源中每一段表达的穷尽版权鉴定；未来接收代码时继续逐项记录来源与许可。
