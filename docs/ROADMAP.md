# 建设计划

## 阶段 0：初始化

- [x] 原仓库连同隐藏文件及 `.git` 迁入参考目录。
- [x] 建立独立资产工程和 Git 仓库。
- [x] 提供 include 路径、C++20 接口目标、安装包配置与最小示例。
- [x] 记录七项用户目标、代码规则和设计边界。

## 阶段 1：用首批可调用资产校准规范

- [ ] 建立最小契约格式、稳定 ID 和校验工具。
- [ ] 收录普通并查集和可回滚并查集，验证状态能力区别。
- [ ] 收录线段树，验证代数条件和底层合并成本。
- [ ] 收录 Dijkstra，验证图结构、权值范围和路径输出。
- [ ] 选择一个数值算法，验证精度和数值契约。
- [ ] 每个资产提供独立头文件、调用示例、正确性依据和必要测试。
- [ ] 校验头文件独立包含、多翻译单元接入和安装后的消费方式。

## 阶段 2：形成可验证的组合

- [ ] 建立“边生存区间 + 时间线段树 + 回滚并查集”配方。
- [ ] 定义重复加边、重边、非法删除和在线/离线条件。
- [ ] 给出整体正确性说明、资源模型和整体测试。
- [ ] 添加有类型的替代、依赖、归约、信息损失和条件冲突关系。

## 阶段 3：以问题为入口检索

- [ ] 形成问题规格字段和输入样例。
- [ ] 实现单算法硬条件匹配和排除理由。
- [ ] 检索已有配方，再在明确的规则与预算内探索组合。
- [ ] 返回适用性、理论资源与实测依据，不伪造运行时保证。
- [ ] 实现条件不足、超预算、未覆盖、搜索未完成等结果。
- [ ] 保存失败案例和能力缺口，作为新增资产的优先依据。

## 阶段 4：强化性能和扩展领域

- [ ] 建立可复现的时间、内存、分配次数基准及平台记录。
- [ ] 按真实需求增补紧凑存储、索引宽度、工作区和历史能力变体。
- [ ] 接入几何、数值优化、ML 和其它语言/后端的领域契约。
- [ ] 对新增资产验证其与现有算法的连接条件。

## 验收原则

能直接调用，能看懂，能判断适用条件，能解释资源成本，能复用已验证组合；找不到时能准确报告当前库的缺口与搜索范围。

不以算法条目数、文档页数或抽象层数作为完成指标。
