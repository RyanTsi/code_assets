# 初始设计约定

## 工程形态

核心为可直接 include 的 C++20 库。公共实现位于 `include/algorithm_assets/`，调用者可以直接配置 include 路径，也可以使用 CMake 接口目标或安装包。算法头文件独立可用，默认不引入运行时注册或虚函数调用。

契约、索引和文档在开发/检索阶段使用，不给算法热路径增加元数据解析成本。未来 Python、ML、GPU 或外部求解器可作为独立实现后端，通过公共语义契约建立关联，不要求复用 C++ 存储布局。

## 四种实体

| 实体 | 职责 |
| --- | --- |
| 问题规格 | 明确结果、结构、操作、精度和资源预算 |
| 算法 | 方法、数学前提和正确性依据 |
| 实现变体 | 具体头文件、API、数据布局、数值与状态策略 |
| 组合配方 | 组件版本、连接条件、整体正确性和资源成本 |

算法名供人学习导航，能力和条件供检索，具体实现供调用。稳定 ID、语义版本与字段格式在首批资产建设时确定，不先造庞大框架。

## 契约最小覆盖面

输入形状与范围、输出语义、空输入和重复项、前置条件、操作与错误行为、整数溢出和浮点精度、随机性、状态改变、所有权和生命周期、历史能力、线程使用、时间成本、常驻/临时/输出空间、来源与验证证据。

已知支持、明确不支持和未知须区分。快照、历史读取、历史修改、回滚、undo、redo、版本分支、版本合并和任意删除分别声明。

成本以具体实现为准，说明初始化、每类操作、保证类型与底层运算成本。大整数运算、矩阵合并不能默认为常数。峰值空间计入同时存活的中间结果、临时工作区、输出及扩容。

## 有类型的关联

替代实现、条件下更优、实现依赖、可连接输入输出、问题归约、性质保持、信息损失、已验证组合与条件冲突应分别表达。组合需要多个前提时，以完整配方表达，不能凭一条“相关”链接证明方案成立。

## 匹配与失败

先规范化需求，再硬条件过滤、适用性验证和资源评估。遵循单算法、已有配方、有限规则内组合的顺序。未知条件不能自动补为有利条件。

输出状态至少区分：找到实现、找到组合、条件不足、现有方案超预算、当前库未覆盖、搜索未完成。报告失败时附目录版本、检查范围、候选被排除的理由与最小缺失能力。不把未找到写成无解，不自动扩充范围或放宽用户要求。

## 性能与可读性

限定计算模型、数据规模、负载和平台后讨论最优性。理论界、字节级存储成本、实测基准与最优性依据分别记录。以少量有意义的实现变体表达时空取舍。

文档从问题和调用例子出发，解释关键不变量、正确性、复杂度、设计选择、替代方案和组合条件。复杂机制必须解释其收益；现代语法不能成为炫技目标。

## 领域扩展

- ML：训练/推理分离、特征语义、拟合状态、随机性和评估质量。
- 优化：目标与约束、梯度、凸性、初值、停止条件、可行性与收敛保证。
- 几何：坐标界、退化输入、精确谓词与精确构造、拓扑和误差传播。

公共契约保持精确结果、概率保证、近似误差和统计评估的区别，不默认将近似输出当作精确输入。
